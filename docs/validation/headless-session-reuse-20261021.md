# 无头查询与本地登录复用验收（2026-10-21）

这是测试候选记录。目标是让用户直接说任务，由程序复用已有站点登录、准备依赖并执行；只有真正缺少登录或需要本人验证时才请用户操作。全部操作只读，未修改上游源码或原浏览器。此记录取代此前“只允许在专用浏览器登录”的候选规则。

## 已改的流程

1. 公开内容仍先用 Agent 已有搜索和读取，足够时直接回答。
2. 需要 Reach 的动作时，普通查询默认无头。先从已连接的本地官方 Browser Bridge 只读复制所需网站 Cookie；不碰密码库、Cookie 数据库或其他网站。
3. 没有来源连接时保留已有 Reach 会话。多个来源不猜账号，选择一次来源；Cookie 复制成功不等于登录已经验证。
4. 本人登录才显窗，定期保存。下一次查询在同一配置转回无头，先恢复会话再打开目标页。
5. 退出或删除渠道后停止自动导入；原浏览器不变。验证码停止，限流暂停一小时，不更换账号或后端重试。

## 修复与边界

- 默认无头已通过实际进程参数验证。显窗、无头切换使用同一配置，Cookie 和 localStorage 在本地测试页上保留；测试页状态随后清除。
- 首次复用小红书前后，来源站点 Cookie 对照一致。凭据只在本机传递，不输出到模型上下文。
- 修复后台执行线程重复获取共享浏览器锁造成的 BUSY。
- BOSS JD 调用上游 `job_card_browser()`，不调用会走独立 HTTP 会话的 `job_detail()` / `job_card()`。短期职位引用保存在渠道私有目录，账号会话改变后失效，不输出 securityId/lid。
- B站用上游官方凭据写入接口，站点登录通过进程标准输入传递。没有可用来源时沿用已保存的原生 CLI 登录；没有字幕与字幕下载失败分别报告。
- 雪球只为社区动作自动同步登录。Node 警告不再盖住真正的上游错误；HTTP 404 不再仅因提示中有 login 字样被归为未登录。
- macOS 回归测试通过；Windows 无头、登录复用和业务动作尚需真机复测。

本轮尚未完成所有登录渠道的目标，不合并、不发布。发布门禁仍要求全部已声明动作的当前源码实测，单元测试不能代替业务结果。候选包不含账号、Cookie、Key、浏览器配置或浏览器二进制。

本轮最终源码：`3ac98c106151237cb8e4deff46d315b23411411e3779d70728c3c0bc756e338f`。18 个动作通过，覆盖 7 类完整渠道和领英 JD；全项目 40 个声明动作中仍有 22 个缺少本次源码的实测，所以发布门禁保持阻断。415 项单测、Ruff 和 Mypy 通过。官方 OpenCLI 1.8.7 的 2,340 个发布文件再次逐字节核对，无修改。

Instagram 在等待期结束后又做了一次低频主页验收，仍返回 HTTP 429，已重新暂停，未尝试其他账号或后端。安装后的命令已成功查询小红书；重新启动的实际进程带 headless 参数，官方扩展已连接，Cursor 配置前后校验一致。

## 本轮继续核验

- 领英 JD 在现有官方 1.8.7 正式路由上通过。搜索故障定位到中文账号界面与英文 Jobs 等待不匹配；试过浏览器语言设置后仍失败，已撤回该尝试，没有强制更改所有网站的界面语言，也未新增第二套后端。
- Cookie 复用改成该站快照，清掉专用浏览器中来源没有的旧 Cookie，保留其他网站；导入失败尝试回滚并保留保存的快照。真实 CDP 测试验证旧 Cookie 消失、其他网站 Cookie 不变，测试数据已清除。
- 更换来源保留明确退出和本人手动登录的选择，不会让已退出渠道自动重新登录。
- 原生 B站字幕不再被可选 OpenCLI 来源发现拦住。模拟未安装 OpenCLI 的运行环境后，真实 B站 CLI 仍取到 979 字字幕；这项额外诊断不重复计入 18 个正式动作。
- 修正两个仅在 POSIX 成立的测试断言，保留 Windows 真机业务验收待办。415 项单测、Ruff、Mypy 通过。

本目标共 22 个登录相关动作，当前 18 个通过，剩余为领英搜索及 Instagram 搜索、主页、帖子。遇到明确限流后停止请求，不自动切换账号或后端。目标保持未完成，PR 保持草稿。

## 用户确认网页正常后的 Instagram 对照

用户确认日常浏览器能查看 NASA 主页和帖子后，等待期结束再做一次正式主页查询。11 项站点 Cookie 已复制，导入后的值与来源一致，无头参数已确认；正式路由本次返回 HTTP 401。随后打开专用浏览器里的 NASA 公开主页，可以看到简介和 12 个帖子链接，但显示为访客，导入的认证 Cookie 已不在目标浏览器中。复制成功不能计作认证通过，帖子链接也不计作帖子正文。

为区分浏览器环境和接口路径，在原浏览器已打开、显示登录账号和内容的 Instagram 页面中，只读请求同一个上游主页接口一次：返回 HTTP 429 和 HTML，原页面地址保持不变。使用官方 Bridge 的临时绑定，结束时解除绑定并恢复原先选中的标签页；未切换账号、修改上游、要求重新登录或继续请求搜索和帖子接口。程序记录了一小时渠道保护；期限结束也不自动重试。

据此，原浏览器网页可见与结构化接口可用是两项能力。当前证据同时暴露接口拒绝请求和专用环境认证未通过，不能将故障全部归为用户未登录、Cloak 检测或全站不可访问。现阶段可用网页工具读取公开页面，Instagram 的三个正式动作继续保留未通过状态。本机脱敏记录与失败结果已保存，未将临时诊断写成新的网页抓取后端。
