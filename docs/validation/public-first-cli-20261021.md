# CLI 先公开访问，再按需使用站内能力

2026-10-21，本机候选版验证。当前改动位于功能分支，尚未发布。

后续[全环节复验](full-reacceptance-20261021.md)发现，公开优先尚未覆盖所有旧路径：未登录的 gh 会阻断 GitHub 公开 API，execute 查雪球行情仍准备浏览器。本文保留这轮已经取得的样本，不代表全项目均已解决不必要登录或配置。

## 执行顺序

1. 先验证参数。带 `public_web` 声明的搜索、阅读动作复用现有 Web 渠道，不先安装浏览器或导入登录。
2. 返回公开结果时标记 `backend: public-web`；`meta.access.scope` 区分 `search_results` 与 `page_text`，不承诺完整性和实时性。
3. 公开访问不足或服务失败后，才尝试所选动作的站内工具；优先复用已有会话。实际站内路径返回 `NEED_LOGIN` 才提示用户本人登录。
4. 页面正文旁的登录链接不构成登录墙；空壳、明确登录页不当作正文。搜索为空、DNS/TLS、403、超时和服务错误都不能单独证明用户需要登录。
5. `--backend public-web` 限定公开访问；指定已声明的站内后端可直接获得站内结果。`execute` 支持相同选择。`ensure` 验收站内能力；`resume` 验证实际待完成的站内动作，避免用公开索引命中掩盖认证失败。

公开路径声明覆盖：LinkedIn jobs/read、Reddit search/read、小红书 search/read、BOSS search/read、X search、Facebook search。其他渠道已有的公开原生接口保持原流程。Instagram 搜用户、评论、字幕、账号列表等独立动作保留原语义，不用网页摘要替代。

公开路径仍使用既有 Exa/Jina 服务。Exa 响应传输截断时，只在原时间预算内补试一次；HTTP 429、403 和工具返回的错误不补试。服务限流归属 Web 服务，不写成目标平台的账号限流。

## 代码与验证

- 共用公开路由读取动作声明，未增加站点 DOM 选择器或自写网页提取器。
- LinkedIn 将公开索引里的地区域名、标题式职位链接转换为官方工具接受的标准职位 ID 链接，先校验域名与路径；未修改 OpenCLI 源码。
- 普通命令、通用 read、execute 采用同一公开优先路由；公开成功时跳过站内准备。
- Skill 和安装摘要同步：LinkedIn 显示“找职位、读公开详情”，站内搜索按实际认证结果决定是否登录。
- 448 项自动化测试通过；49 个生产 Python 文件通过 Ruff 和 mypy；安装 wheel 与这 49 个文件逐一比对一致。
- 覆盖无结果/错域名、空壳/登录页、正文附登录链接、短正文、明确认证失败、限流归属、显式后端、恢复待办、冷启动预算及响应截断边界。
- 候选 wheel 排除本机 API 原型、个人配置、Cookie、浏览器目录及已移除的 ask/MCP 模块。本机 CLI 和已安装 Skill 已同步。
